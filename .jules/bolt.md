- In the Angular frontend, memoizing computationally expensive evaluations (like chess.js state checks, `isGameOver`, `isCheckmate`) into state variables and updating them only when necessary (e.g., after `makeAMove`) is crucial. Binding these directly to methods in templates (`*ngIf="game.isGameOver()"`) causes severe performance bottlenecks and freezes during Angular change detection cycles, especially when using complex libraries like `chess.js` or handling frequent timer interval updates.
## 2026-07-06 - [Angular Timer Optimization]
**Learning:** Using `setInterval` inside an Angular component's methods (like `ngOnInit` or custom methods) triggers global change detection across the entire component tree *every single time* the interval fires (e.g., every second). This creates severe performance overhead and freezing, especially when combined with heavy operations or components like chess boards.
**Action:** Always wrap high-frequency intervals (like game timers) inside `this.ngZone.runOutsideAngular(() => setInterval(...))`. Then, when state actually updates and requires a visual change, manually trigger local component updates using `this.cdr.detectChanges()` (or wrapping specific updates in `this.ngZone.run()`).
